# Master Builders

Веб-приложение для строительных, ремонтных и монтажных компаний, у которых работа с бригадами живёт в звонках, чатах и таблицах. Здесь задание, бригада, сроки, обсуждение и фотоотчёт собраны в одной карточке.

Диспетчер ставит задание на объект и бригаду. Бригадир с телефона принимает его, начинает работу, при необходимости отмечает препятствие и отправляет фотоотчёт. Диспетчер принимает результат или возвращает на доработку с замечанием. Руководитель видит всё по своему подразделению, но ничего не меняет.

Сейчас это MVP для пилота в одной компании.

## Что есть

- задания со статусами: назначено → принято → в работе → на проверке → завершено, и отмена с причиной;
- расписание бригад на день, предупреждение о пересечении работ одной бригады до сохранения;
- препятствия на объекте (доступ, материалы, техника): пока препятствие открыто, отчёт отправить нельзя;
- фотоотчёты с версиями: 1–10 фото JPEG, PNG или WebP до 10 МБ, EXIF удаляется на сервере, фото лежат в закрытом хранилище;
- обсуждение и история изменений в каждом задании;
- обзор для диспетчера и руководителя: просрочки, препятствия, ожидание проверки, доля принятых в срок;
- объекты и бригады подразделения;
- списки обновляются сами раз в 30 секунд, время везде по поясу компании (по умолчанию Москва).

## Стек

Next.js 16 (App Router), TypeScript, Tailwind CSS 4, Supabase: Postgres, Auth и Storage. Права проверяются в самой базе: политики RLS на чтение, а все изменения идут через функции, которые проверяют роль, статус и версию задания. Тесты: интеграционные тесты базы на `node:test` и сценарии в браузере на Playwright.

Подробнее про схему данных, права и защиту от повторных запросов: [docs/architecture.md](docs/architecture.md).

## Запуск локально

Понадобятся Node.js 22 и Docker (Docker Desktop, OrbStack или Colima): на нём поднимается локальный Supabase.

    npm ci
    npx supabase start

Первый запуск скачивает образы Supabase, это займёт несколько минут. Миграции и демо-данные из `supabase/seed.sql` применяются автоматически.

Создайте `.env.local` из примера:

    cp .env.example .env.local

и заполните ключи из вывода `npx supabase status -o env` (`ANON_KEY` и `SERVICE_ROLE_KEY`):

    NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
    NEXT_PUBLIC_SUPABASE_ANON_KEY=<ANON_KEY>
    SUPABASE_SERVICE_ROLE_KEY=<SERVICE_ROLE_KEY>
    DEMO_ACCOUNTS=enabled
    DEMO_PASSWORD=demo-pass-2026

Загрузите демо-фото для отчётов и запустите приложение:

    npm run seed:photos
    npm run dev

Приложение откроется на http://localhost:3000.

Остановить: `Ctrl+C` в терминале с `npm run dev`, затем `npx supabase stop`. Начать с чистой базы: `npx supabase db reset` и снова `npm run seed:photos`.

Письма восстановления пароля локально никуда не уходят, их можно посмотреть в Mailpit: http://127.0.0.1:54324.

## Короткий сценарий демонстрации

1. Войдите диспетчером «Север». На обзоре видно, что просрочено, где препятствие и какой отчёт ждёт проверки. Счётчики открывают отфильтрованный список.
2. Создайте задание на бригаду монтажа №1 на сегодня с 13:00 до 16:00. Система предупредит, что у бригады в это время уже есть работы, но сохранить можно.
3. В другом браузере или в окне шириной с телефон войдите бригадиром Петровым. Примите задание, начните работу, отправьте отчёт с парой фото.
4. Вернитесь к диспетчеру: верните отчёт с замечанием. Бригадир увидит замечание и отправит вторую версию, первая останется в истории.
5. Примите вторую версию. Задание завершено и попадает в показатели на обзоре руководителя.

## Права

|                                           | Диспетчер            | Бригадир             | Руководитель         |
| ----------------------------------------- | -------------------- | -------------------- | -------------------- |
| Видит задания                             | своего подразделения | только своей бригады | своего подразделения |
| Создаёт, меняет сроки и бригаду, отменяет | да                   | нет                  | нет                  |
| Принимает задание, отправляет отчёт       | нет                  | да                   | нет                  |
| Принимает или возвращает отчёт            | да                   | нет                  | нет                  |
| Открывает препятствие                     | нет                  | да                   | нет                  |
| Закрывает препятствие                     | да                   | да                   | нет                  |
| Пишет в обсуждение                        | да                   | да                   | только читает        |

Регистрации нет: компания, подразделения, бригады и сотрудники создаются через seed или администратором базы.

## Правила сроков

- Начало всегда раньше окончания. Соседние интервалы (одно заканчивается в 12:00, другое начинается в 12:00) не считаются пересечением.
- Исходный срок не меняется. Перенос меняет текущий срок и сохраняет причину, старое и новое значение.
- Просрочка исполнения: текущее окончание прошло, а задание ещё назначено, принято или в работе. Препятствие просрочку не отменяет.
- Ожидание проверки считается отдельно от просрочки бригады: если отчёт отправлен, задержка уже на стороне диспетчера.
- «В срок» оценивается по времени отправки принятой версии отчёта отдельно для исходного и для текущего срока. Отменённые задания в долю не входят.

## Проверки

    npm run typecheck
    npm run lint
    npm run build

Тесты базы создают отдельную чистую базу, применяют миграции и seed. По умолчанию нужен Postgres на `127.0.0.1:5432`, но подойдёт и база локального Supabase:

    TEST_ADMIN_DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:54322/postgres npm run db:test:prepare
    TEST_DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:54322/master_builders_test npm run test:db

Сценарии в браузере запускаются на работающем приложении с демо-данными, свои задания они создают и отменяют сами:

    npm run test:e2e
